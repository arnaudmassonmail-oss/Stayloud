# STAYLOUD v5.16 — identité artiste canonique

## Correction principale

v5.15 pouvait trouver une bonne fiche MusicBrainz sans utiliser son nom canonique pour les autres moteurs.
Exemple : `Landmarks` pouvait être résolu vers `LANDMVRKS` pour la fiche, mais les recherches concerts continuaient avec `Landmarks`.

v5.16 corrige cela :
- à l'ajout, le nom canonique retourné par MusicBrainz est désormais enregistré ;
- à chaque actualisation, l'identité MusicBrainz est vérifiée et le nom canonique est répercuté dans l'artiste suivi ;
- les recherches Bandsintown, InfoConcert et lineup utilisent donc le vrai nom ;
- le résolveur MusicBrainz effectue plusieurs recherches et un classement de candidats pour mieux gérer les variantes/fautes de saisie ;
- migration concert vers 5.16 : les anciens concerts sont reconstruits avec le moteur actuel.

## Cas corrigé

`Landmarks` → `LANDMVRKS`.
Le moteur ne doit plus chercher les concerts sous `Landmarks`, et le profil ne doit plus récupérer une homonymie musicale de type Klaxons.

## Vérification

Syntaxe Node vérifiée sur : server, aggregator, db, musicbrainz et concert-web.
Le réseau externe n'a pas été exécuté dans l'environnement de build ; le test réel doit être fait dans l'installation STAYLOUD avec accès Internet.
